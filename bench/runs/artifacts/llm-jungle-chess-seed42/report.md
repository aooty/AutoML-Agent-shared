# AutoML 실행 리포트 — `jungle-chess`

## 요약

목표는 달성되었습니다. 목표 지표 `balanced_accuracy`의 임계값 0.633에 대해, 첫 번째 시도인 `hist_gbdt`가 검증 슬라이스에서 **0.7957** (95% CI 0.7858~0.8073)을 기록했고, 한 번도 사용되지 않은 최종 테스트 20%에서 **0.7864** (95% CI 0.7753~0.7971)를 기록했습니다. 두 수치 모두 임계값 0.633과 `logreg` 베이스라인 0.5106 (CI 0.5024~0.5177)을 크게 상회합니다. 총 5회 예산 중 **1회**만 사용하고 목표 달성으로 조기 종료되었습니다.

## 최고 성능 구성

iteration 1, `hist_gbdt`. 아래 값은 해당 시도의 히스토리에 기록된 **적용된** 값입니다.

- `hyperparams`: `max_iter=600`, `learning_rate=0.1`, `max_leaf_nodes=128`, `l2_regularization=0.1`, `early_stopping=false`, `max_depth=12`
- `preprocessing` (적용값): `impute=median`, `scale=false`, `missing_indicator=false`, `missing_count=false`
- 입력: 카드의 6개 numeric 열 그대로 (결측률 0.0), 파생·인코딩·삭제 없음
- 프로토콜: stratified 3분할, train 0.6 / val 0.2 / test 0.2, seed 42 (베이스라인과 동일 분할)
- 학습 시간: 19.044초

## 원인 분석

이 실행에서 critic은 **한 번도 실행되지 않았습니다** (시도 1회, 진단 0회). 첫 계획이 곧바로 임계값을 넘겨 루프가 종료되었기 때문에, 설명할 "진단 패턴"이 존재하지 않습니다. 따라서:

- 점수 0.7957(검증) / 0.7864(테스트)는 **첫 번째 계획 하나가 낸 결과**입니다. 진단·재계획 경로는 이 결과에 전혀 기여하지 않았고, 이 실행은 그 경로가 유용하다는 증거도, 해롭다는 증거도 제공하지 않습니다.
- 시도가 1건이므로 시도 간 비교도 없습니다. 구간이 겹치는 시도들 사이의 변동을 해석하는 문제 자체가 발생하지 않았습니다.

무엇이 성능을 제한했는지에 대한 진단은 **내려지지 않았습니다**. 관측 사실만 그대로 적어 두면 다음과 같습니다 (이는 진단이 아니라 계측값입니다).

- 선형 베이스라인 `logreg`는 0.5106 (CI 0.5024~0.5177)였고, `hist_gbdt`는 0.7957이었습니다. 두 구간은 겹치지 않으므로 모델 계열(family) 전환분은 이 데이터로 분리 가능한 실제 차이입니다.
- `train_balanced_accuracy` 0.9957 대 검증 0.7957, 즉 `train_val_gap` = 0.1999로 학습 데이터에는 거의 완전 적합했습니다. 이는 `max_leaf_nodes=128`, `max_depth=12`, `max_iter=600`, `early_stopping=false` 구성과 일관되지만, 이 간격을 줄이면 검증 점수가 올라간다는 증거는 이 실행 안에 없습니다.
- 이 시도의 `metrics`에는 `balanced_accuracy_at_best_cut` / `cut_headroom` / `brier` / `calibration_error`가 없습니다(3-클래스 과제). 따라서 남은 격차가 **랭킹 축**에 있는지 **작동점(operating point) 축**에 있는지 판정할 수 있는 수치가 이 실행에는 존재하지 않습니다. 클래스 분포가 0.5146 / 0.3887 / 0.0967 (imbalance_ratio 5.32)이므로 최소 클래스의 작동점 손실 가능성은 남아 있으나, 이는 가설이며 측정된 바 없습니다.

## 다음 단계 제안

데이터 카드에 별도의 caveat이 기록되어 있지 않으므로(`없음`), 아래 제안은 어느 열·값·분할의 신뢰성 문제에도 걸리지 않습니다. 결측률이 0.0이므로 `missing_indicator` / `missing_count` / `impute: none` 계열의 실험은 전부 무의미하며 예산을 쓸 가치가 없습니다.

1. **정규화 강화 버전을 1회 붙여 `train_val_gap` 0.1999가 회수 가능한지 측정.** 동일 `hist_gbdt`에서 `max_leaf_nodes`를 31~63으로, `max_depth`를 6~8로 낮추고 `l2_regularization`을 1.0~10.0으로 올려 1회만 돌립니다. 판단 기준은 검증 CI 폭(약 ±0.011)보다 큰 변화가 있는지 여부입니다 — 그보다 작은 차이는 개선으로 보고하지 않아야 합니다. `early_stopping=true`는 train 10%를 소모하므로, 켤 경우 `internal_validation`의 행 수를 함께 읽어야 합니다.
2. **최소 클래스(0.0967)에 대한 작동점 레버를 실제로 시험.** 이번 계획은 "이 estimator에서 `class_weight`를 쓸 수 없다"고 가정한 채 기본 argmax로 남겼고, 그 가정은 검증되지 않았습니다. `class_weight='balanced'` 또는 세 클래스를 모두 정확히 한 번 덮는 명시적 가중치 맵을 넣어 1회 돌리면, 적용되었는지 여부가 `dropped_hyperparams`에 그대로 드러납니다. 적용된다면 클래스별 `recall` 변화로 작동점 축의 크기를 직접 읽을 수 있습니다.
3. **계열 교체를 1회로 한정해 확인:** 동일 전처리에서 `xgboost`(또는 `random_forest`)로 교체. 문서화된 경험치상 계열 교체의 효과 폭은 고정되어 있지 않으므로(0.0022~0.0077 수준의 사례가 있음), 이번 CI 폭 안에 묻힐 가능성이 큽니다 — "차이 없음"으로 끝나도 그것이 유효한 결론이라고 보고할 수 있게 사전에 기준을 정해 두십시오.
4. **executor 밖에서 특징을 만들어 카드에 넣는 것을 검토.** 이 executor는 파생·상호작용·재인코딩을 전혀 하지 않으며, 현재 입력은 `white_piece0_strength/file/rank`, `black_piece0_strength/file/rank` 6개 원본 열뿐입니다. 강함 차이나 파일/랭크 거리 같은 도메인상 자연스러운 조합은 계획으로는 요청할 수 없고 **카드(데이터 파일)에 열로 추가되어야** 합니다. 이는 랭킹 축을 직접 넓히는 유일한 경로이며, 위 1~3이 CI 폭 안에서 정체될 경우 다음으로 투자할 곳입니다.
